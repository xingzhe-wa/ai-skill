# USER

## 用户偏好

用户偏好中文沟通。

用户希望回答直接、具体、可执行，避免泛泛解释、重复背景和无效铺垫。

用户关注 token 成本。长流程、安装教程、排障手册、命令清单应放到 docs 文档中；长期记忆只保留稳定偏好、关键边界和文档入口。

## 工程协作偏好

明确任务默认直接执行，不要频繁要求用户确认。

不允许私自执行 git commit。

不允许私自执行以下高风险操作：

- `git reset --hard`
- `git clean -fdx`
- `git push --force`
- 递归删除用户目录
- 递归删除系统目录
- 未确认的强制覆盖操作

代码或配置任务完成时，应输出：

- 改动文件
- 核心改动
- 验证命令
- 测试结果
- 未验证项
- 剩余风险

## Hermes 使用偏好

用户希望把 Hermes 作为 Vibe Coding 调度中心使用。

Hermes 的主要职责是：

- 需求澄清
- 任务拆分
- 长期记忆维护
- 上下文管理
- 多 agent 协作
- 调度 Codex / Claude Code
- 汇总执行结果
- 最终验收

Codex / Claude Code 作为 coding worker，负责具体读代码、改文件、跑测试、修复问题和交付 diff。

微信/飞书/QQ/Hermes cli等网关可以作为需求入口，但任务边界、项目路径、约束条件和验收标准必须明确。
